Important

In scanner mode, PyRIT uses Microsoft datasets and techniques — not your hand-written payloads. Your job is to expose the lab as a registered HTTPTarget.

2. Lab HTTP contract

Request

POST /chat HTTP/1.1
Host: 127.0.0.1:5000
Content-Type: application/json
Cookie: session=<YOUR_SESSION_COOKIE>
Connection: close

{"message":"hello","mode":"vulnerable"}

Response

Model text is in the response field:

{
  "response": "Hello! How can I assist you today?",
  "flag_found": false,
  "lab": "Basic Prompt Injection",
  ...
}

PyRIT fills {PROMPT} into the JSON body and parses the reply from response.

4.1 register_playground_target.py

Why

pyrit_scan only talks to registered targets. The lab is not OpenAI-shaped, so wrap it in HTTPTarget and register playground_chat.

# register_playground_target.py
"""Register the lab /chat endpoint as a PyRIT target."""

from __future__ import annotations

import json
from pyrit.prompt_target import HTTPTarget
from pyrit.registry import TargetRegistry
from pyrit.setup.initializers import PyRITInitializer

# Paste a FRESH session cookie when the old one expires.
SESSION_COOKIE = (
    "session=eyJzZXNzaW9uX2lkIjoiZDQxMThmODUtZThhMC00NzViLWE3MWItMTU4NDliYzY3YTBlIn0."
    "amnCnw.V0OrMjRGBu4HaFfcdsadMmnED-4"
)

# {PROMPT} is replaced by PyRIT. Cookie uses f-string; JSON braces are doubled.
RAW_HTTP = f"""\
POST /chat HTTP/1.1
Host: 127.0.0.1:5000
Content-Type: application/json
Accept: */*
Origin: http://127.0.0.1:5000
Referer: http://127.0.0.1:5000/
Cookie: {SESSION_COOKIE}
Connection: close

{{"message":"{{PROMPT}}","mode":"vulnerable"}}
"""


def parse_response(response: str) -> str:
    try:
        data = json.loads(response)
        text = data.get("response")
        return str(text) if text is not None else response
    except Exception:
        return response


class PlaygroundChatTargetInitializer(PyRITInitializer):
    """Registers target name: playground_chat"""

    async def initialize_async(self) -> None:
        target = HTTPTarget(
            http_request=RAW_HTTP,
            prompt_regex_string="{PROMPT}",
            callback_function=parse_response,
            use_tls=False,  # http:// not https://
            timeout=60.0,
        )
        registry = TargetRegistry.get_registry_singleton()
        # Name is a keyword argument (positional name, target fails on this API)
        registry.instances.register(target, name="playground_chat")

Critical details

Placeholder is {PROMPT} (must match prompt_regex_string). Use use_tls=False for plain HTTP. Register with register(target, name="playground_chat") — not register("name", target).

4.2 scanner.env

Why

Built-in scorers and multi-turn attackers need a chat model. These vars configure the judge/attacker — they do not replace the lab target.

# Judge / helper (LM Studio)
OPENAI_CHAT_ENDPOINT=http://127.0.0.1:1234/v1
OPENAI_CHAT_MODEL=meta-llama-3-8b-instruct
OPENAI_CHAT_KEY=lm-studio

# Multi-turn adversarial model (can be the same)
ADVERSARIAL_CHAT_ENDPOINT=http://127.0.0.1:1234/v1
ADVERSARIAL_CHAT_MODEL=meta-llama-3-8b-instruct
ADVERSARIAL_CHAT_KEY=lm-studio
  • Model name must match LM Studio’s /v1/models
  • Endpoint must include /v1
  • For OpenAI cloud: real API key, https://api.openai.com/v1, model like gpt-4o-mini

4.3 pyrit_custom_scan.yaml

Why

One place to enable custom initializers, load env, run standard target/scorer/technique setup, then run your script.

memory_db_type: in_memory
allow_custom_initializers: true
env_files:
  - ./scanner.env
initializers:
  - name: target
    args:
      tags:
        - default
        - scorer
  - name: scorer
  - name: technique
    args:
      tags:
        - all
  - name: load_default_datasets
initialization_scripts:
  - ./register_playground_target.py
KeyWhy
allow_custom_initializers: trueRequired or custom scripts are rejected
env_filesLoads OPENAI_CHAT_* for the judge
target + scorerRegisters OpenAI-compatible targets and LLM scorers
technique + load_default_datasetsLoads techniques and Microsoft datasets
initialization_scriptsRuns your lab registration on backend startup

5. Startup sequence (order matters)

A. Services up

  1. Lab on :5000
  2. LM Studio server on :1234
  3. All three project files in one directory

B. Start PyRIT backend

cd C:\Users\<you>\Downloads\aaaz

pyrit_scan --stop-server
pyrit_scan --start-server --config-file ./pyrit_custom_scan.yaml

Success looks like

Server ready (PID ...). Server is running at http://localhost:8000

C. Verify targets

pyrit_scan --list-targets

Expected:

adversarial_chat   OpenAIChatTarget  → LM Studio
openai_chat        OpenAIChatTarget  → LM Studio
playground_chat    HTTPTarget        → http://127.0.0.1:5000/chat

If playground_chat is missing, check %TEMP%\pyrit_backend.log.

6. Run scans — command patterns

Leave the server running. Always pass --target playground_chat.

Leakage (best first test for secret/PIN labs)
pyrit_scan airt.leakage --target playground_chat --techniques single_turn --max-dataset-size 5

REM Or scenario default technique:
pyrit_scan airt.leakage --target playground_chat --max-dataset-size 5
Jailbreak
pyrit_scan airt.jailbreak --target playground_chat --techniques prompt_sending --max-dataset-size 5
Aggregate vs concrete technique
REM Aggregate expands to a set defined by the scenario
pyrit_scan airt.leakage --target playground_chat --techniques single_turn --max-dataset-size 10

REM Concrete technique
pyrit_scan airt.leakage --target playground_chat --techniques role_play_persuasion --max-dataset-size 5

REM Multi-turn (needs adversarial chat — already in scanner.env)
pyrit_scan airt.leakage --target playground_chat --techniques multi_turn --max-dataset-size 3
Discovery
pyrit_scan --list-scenarios
pyrit_scan airt.leakage --help
pyrit_scan --list-datasets
pyrit_scan --list-targets

Always trust your install

Run pyrit_scan --list-scenarios on the machine you use. Technique names can differ slightly between releases.

7. What each command does

pyrit_scan airt.leakage --target playground_chat --techniques single_turn --max-dataset-size 5
         │              │                        │                      │
         │              │                        │                      └─ only 5 dataset rows (faster)
         │              │                        └─ which attack strategies to run
         │              └─ send attacks to YOUR lab (HTTPTarget)
         └─ scenario = objective + default datasets + scorers + technique catalog
  1. Load objectives from the scenario dataset (e.g. leakage prompts).
  2. Apply technique (encoding, role-play, multi-turn, …).
  3. Send HTTP request to the lab with {PROMPT} filled in.
  4. Parse the response JSON field.
  5. Score with the LLM judge (openai_chat → LM Studio) or scenario-specific scorers.
  6. Report success / fail.

How to read this table

  • Aggregates — named groups passed to --techniques (e.g. single_turn, all). They expand to multiple concrete techniques.
  • Available techniques — concrete attack names you can pass individually.
  • Default technique — used when you omit --techniques.
  • Default datasets — objectives loaded unless you override with dataset options.

Psychosocial note

airt.psychosocial also has a separate sub_harm parameter (imminent_crisis, licensed_therapist, or all). That is not a --techniques value. Techniques in that scenario are mostly converter layers on a simulated-crescendo base.

9. Troubleshooting

SymptomCauseFix
Custom initializer operations are disabled Flag off or old server process Set allow_custom_initializers: true in .pyrit_conf and project YAML; fully stop and restart backend
Environment file not found: ...\scanner.env Missing file Create scanner.env next to the YAML
Configuration file not found: ...yam Typo in filename Use .yaml (not .yam)
register() takes 2 positional arguments but 3 were given Wrong registry API register(target, name="playground_chat")
Target missing from --list-targets Initializer failed Read %TEMP%\pyrit_backend.log
401 / empty from lab Stale session cookie Refresh SESSION_COOKIE, restart server
Scorer / json_object errors LM Studio vs structured output Stronger model, cloud judge, or compatibility proxy
Server already running; config ignored Old process still bound to :8000 pyrit_scan --stop-server or kill PID on port 8000
