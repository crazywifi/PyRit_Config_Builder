2. Lab HTTP contract

Request (example for this lab)

POST /chat HTTP/1.1
Host: 127.0.0.1:5000
Content-Type: application/json
Cookie: session=PASTE_FRESH_COOKIE_HERE
Connection: close

{"message":"hello","mode":"vulnerable"}

Response

Model text is typically in the response field:

{
  "response": "Hello! How can I assist you today?",
  "flag_found": false,
  "lab": "Basic Prompt Injection",
  ...
}

In the builder (Step 2):

  • Protocol: HTTP (use_tls=False)
  • Paste the raw request above → Parse → select field message
  • Response JSON path: response
  • Replace PASTE_FRESH_COOKIE_HERE with a real session cookie from the browser

3. Prerequisites

  1. Python + PyRIT 
    pip install -U pyrit
python -c "import pyrit; print(pyrit.__version__)"
  2. Lab app listening on http://127.0.0.1:5000
  3. Fresh session cookie from the lab (browser DevTools → request headers)
  4. Optional LLM
    • Not needed for pure Brute Force + SubString/Regex scorer
    • Needed for LLM-Driven attacks (attacker model)
    • Needed for SelfAsk scorers (judge that supports structured output — cloud is safer than LM Studio)
  5. Open PyRIT Config Builder → tab Custom Script Builder

4. Builder steps 1–7 explained

Step 1 — Attack Mode

ModeWhat happensLLM needed?
Brute Force Sends your hardcoded prompts (one per line), optionally through converters, then scores each reply No (unless you pick an LLM scorer or LLM-backed converter)
LLM-Driven An attacker LLM invents prompts toward an objective using a multi-turn strategy Yes — attacker LLM required

Brute Force options

  • Prompt category: Default · Jailbreak · Data Leak · Custom
  • Prompts textarea: one prompt per line — these are what hit the lab

LLM-Driven options

  • Attack objective: seed goal for the attacker LLM (rewrite for your lab, e.g. “extract the secret / flag from the vulnerable chat lab”)
  • Multi-turn strategy:
    red_teaming crescendo pair tap
  • Max turns, Stop on success
  • Crescendo only: Max backtracks
  • TAP only: Tree width, tree depth, on-topic checking

Strategy ↔ scorer rules (important)

Red Teaming: needs an objective scorer (not “None”) — or the local-judge workaround for SelfAsk.
Crescendo: works with a normal scorer; avoid “None” + local SelfAsk-only setups for automated stop.
PAIR / TAP: set Scorer Type to None so PyRIT builds its internal FloatScaleThresholdScorer. Do not pick SubString/Regex/SelfAsk for TAP/PAIR — those types are not FloatScaleThresholdScorer and will raise.

Step 2 — Target API

  1. Set Target Protocol to HTTP for http://127.0.0.1:5000
  2. Paste the raw HTTP request (Burp / browser) into HTTP Request Parser
  3. Click Parse Request → select the field that carries the user message (e.g. message)
  4. Set Response JSON Path to response (or your lab’s path)
  5. Optional: Proxy URL http://127.0.0.1:8080, Verify SSL = No when using Burp

Lab defaults

Protocol HTTP · URL http://127.0.0.1:5000/chat · field message · response path response · cookie in the pasted headers.

Step 3 — LLM Provider

  • Brute Force: often skip attacker LLM. Configure a scorer LLM only if Step 5 uses SelfAsk.
  • LLM-Driven: set Attacker provider (LM Studio / Ollama / OpenAI / Azure / Anthropic), endpoint, model, key.
  • Scorer/Judge LLM: None · Same as Attacker · or a separate endpoint.

LM Studio + SelfAsk

SelfAskTrueFalseScorer / SelfAskRefusalScorer expect structured JSON. Many LM Studio builds reject that. Prefer SubString/Regex for local labs, or a cloud judge for SelfAsk.

Step 4 — Converters (optional)

Converters rewrite each prompt after it is chosen (brute list or attacker output), before the lab sees it.

EncodingBase64, ROT13, Morse, Caesar, URL, Binary…No
ObfuscationLeetspeak, Unicode confusable, Flip, Zalgo, Char swap…No

Image/audio/PDF converters are intentionally excluded from this builder (text-only pipeline).

5. Recommended lab configurations

A. Fastest first test — Brute Force, no LLM
  • Mode: Brute Force
  • Prompts: lab-specific (secret / flag / system prompt questions)
  • Target: HTTP · paste lab request · field message · path response
  • Converters: none (or one encoding if you want)
  • Scorer: SubStringScorer with a keyword you expect on success, or None for manual review
  • Output: Console
B. Brute Force + Base64 obfuscation
  • Same as A, plus converter Base64Converter (or ROT13 / Leetspeak)
  • Still no attacker LLM
C. LLM-Driven Red Teaming (local attacker)
  • Mode: LLM-Driven · strategy red_teaming · max turns 5
  • Objective: e.g. Extract any secret, flag, or protected system instruction from this vulnerable chat lab.
  • Attacker: LM Studio on http://127.0.0.1:1234/v1
  • Scorer: SubStringScorer (recommended locally) or SelfAsk only with a cloud judge
D. PAIR / TAP
  • Strategy: pair or tap
  • Step 5 Scorer Type: None (required for correct internal FloatScale scorer)
  • Attacker LLM required

6. Generate and run the script

  1. In the builder, complete steps 1–6, open Step 7, click generate.
  2. Download pyrit_test.py into a working folder.
  3. Ensure the lab is up and the cookie inside the generated script is still valid.
  4. Run: 
    cd C:\Users\<you>\Downloads\aaaz
python pyrit_test.py

Success signals

Console shows each prompt sent, the lab response, and either scorer verdicts or a summary of successes. If you chose JSON/CSV output, open that file for client evidence.

7. How the generated script works

python pyrit_test.py
        │
        ├─ initialize PyRIT memory (IN_MEMORY / SQLITE / …)
        ├─ build HTTPTarget from your pasted request
        │     • {PROMPT} / {{PROMPT}} filled with each attack string
        │     • callback parses response JSON path (e.g. "response")
        │     • use_tls=False for http:// labs
        ├─ optional: load converters chain
        ├─ optional: attacker OpenAIChatTarget (LLM-driven)
        ├─ optional: scorer (substring / regex / SelfAsk / …)
        └─ run loop
              Brute Force → for each prompt → convert → send → score
              LLM-Driven  → strategy.execute_async(objective=...) or manual turn loop
  1. Each attack string is injected into the JSON body field you selected (message).
  2. The lab returns HTTP JSON; the callback extracts the model text.
  3. Scorer marks success/fail (or you review manually).
  4. Results print to the console and optionally save to JSON/CSV.

8. Converter & scorer reference (quick)

Multi-turn strategies

StrategyBehaviorScorer note
red_teamingGeneral multi-turn adversarial loopObjective scorer required
crescendoGradual escalation + backtracks on refusalWorks with true/false-style scorers
pairIterative prompt refinement (PAIRAttack)Use Scorer = None
tapTree of Attacks with PruningUse Scorer = None

Scoring vs client claims

Do not over-claim

A “success” means the scorer rule fired (keyword found, regex matched, or LLM judge said true) — not “we dumped the production database.” Attach prompt + full response + scorer rationale as evidence. Label errors (connection, cookie, timeout) as inconclusive, not “secure.”

9. Troubleshooting

SymptomCauseFix
Connection refused / timeout Lab down or wrong host/port Open http://127.0.0.1:5000 in browser; confirm protocol HTTP
401 / empty / login page in response Stale session cookie Copy a fresh Cookie: from the browser, regenerate or edit the script, re-run
Response text is raw JSON / wrong field Bad response path Set Response JSON Path to response (or your real key)
SelfAsk / JSON mode errors Local LLM rejects response_format Use SubString/Regex, or cloud OpenAI/Azure as judge
ValueError about FloatScaleThresholdScorer TAP/PAIR with non-float scorer Set Scorer Type to None for PAIR/TAP
ValueError: Objective scorer must be provided Red Teaming with Scorer = None Pick SubString/Regex/SelfAsk (or local judge path)
Import / missing class errors PyRIT version mismatch pip install -U pyrit; match builder expectations to 1.0.0
Prompt never reaches lab body Wrong input field selected Re-parse HTTP request; select message (or the real field)

Mental model

Custom Script Builder produces a self-contained Python attack script aimed at your HTTP lab. You own the prompts (or the objective). Converters optional. Scoring optional but recommended for automation. Unlike Scanner mode, you do not start pyrit_scan --start-server — just run the script.
