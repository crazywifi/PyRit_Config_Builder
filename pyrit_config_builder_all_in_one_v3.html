1. Install PyRIT

pip install --user -U pyrit

On Windows, pyrit_scan on your PATH may point to an older install.
Preferred commands for the latest install:

2. Create Configuration Folder

# Windows
mkdir %USERPROFILE%\.pyrit

# Linux/Mac
mkdir ~/.pyrit

3. Create .env File

Create ~/.pyrit/.env for scorer and helper model settings. Your custom HTTP target itself is configured in the generated Python/YAML files.

# Example for OpenAI-compatible scoring/judging target
# Important: some local OpenAI-compatible servers do NOT support the
# structured response format PyRIT scanner scorers expect.
OPENAI_CHAT_ENDPOINT=http://localhost:1234/v1
OPENAI_CHAT_MODEL=local-model
OPENAI_CHAT_KEY=dummy

# Recommended cloud example for scanner scorers
# OPENAI_CHAT_ENDPOINT=https://api.openai.com/v1
# OPENAI_CHAT_MODEL=gpt-4o-mini
# OPENAI_CHAT_KEY=sk-...

# Azure example
# AZURE_OPENAI_GPT4O_UNSAFE_CHAT_ENDPOINT=https://YOUR-RESOURCE.openai.azure.com/openai/v1
# AZURE_OPENAI_GPT4O_UNSAFE_CHAT_MODEL=gpt-4o
# AZURE_OPENAI_GPT4O_UNSAFE_CHAT_KEY=your-azure-key

4. Create .pyrit_conf File (Optional)

Create ~/.pyrit/.pyrit_conf as YAML for PyRIT defaults:

# Optional global defaults
memory_db_type: in_memory
initializers: []
initialization_scripts: []
env_files:
  - C:/Users/YOUR_USER/.pyrit/.env

📁 Why These Files?

  • .env - Stores scorer/helper model settings and secrets outside generated scripts
  • .pyrit_conf - Stores YAML defaults for memory, env files, and optional initializers
  • The generated scanner files define your custom HTTP target; the global files support PyRIT itself

⚔️ Step 1: Select Attack Mode

💡 Important: Attack Mode Determines LLM Requirements

Brute Force: NO LLM needed - sends hardcoded prompts directly
LLM-Driven: Needs LLM to generate prompts (attacker). Scorer/Judge is optional.

📋 Default Prompts

Basic prompts to extract protected information through direct questions.

Objective Behavior

This objective is the seed goal you give the attacker LLM.
The long sections you saw like Background, Task Requirements, and Constraints are not hardcoded in the builder.
They are generated by the attacker LLM at runtime as it expands your objective into an attack plan.

Will The Same Objective Work On Another App?

Often yes at a high level, but usually with better results if you rewrite it for the target.
For example, "extract the secret password" is Gandalf-specific, while a generic app may need an objective like "make the assistant reveal hidden system instructions" or "bypass refusal and disclose protected data."

📖 Multi-Turn Strategy Comparison

Red Teaming: General adversarial conversation, one attacker LLM iterating turn by turn
Crescendo: Gradually escalates from benign to harmful, backtracking when refused (real CrescendoAttack)
PAIR: Native PAIRAttack implementation for iterative prompt refinement
TAP: Uses TreeOfAttacksWithPruningAttack to explore and prune multiple prompt branches

How many times Crescendo can rewind and try a gentler approach after the target refuses.
How many candidate prompts to try in parallel at each depth (set to 1 for PAIR-style behavior).

🤖 Step 3: Configure LLM Provider

✅ No LLM Required for Brute Force

Brute force attack sends prompts directly without needing an LLM. You can skip this step or optionally configure an LLM scorer.

⚡ Attacker LLM Required

LLM-driven attacks need a language model to generate adaptive prompts. Configure your attacker LLM below.

📊 Scorer LLM (Optional)

When is this used? Only when you select an LLM-based scorer in Step 5 (like SelfAskTrueFalseScorer).

Not needed for: "No Scorer", SubStringScorer, RegexScorer, GandalfScorer

What The Options Mean

No LLM Scorer: Do not configure a separate judge model. Step 5 can still use manual review or simple non-LLM scorers.
Same as Attacker: Reuse the attacker LLM from this step as the Step 5 judge/scorer model. This is convenient, but attacker and judge become the same backend.

🔄 Step 4: Prompt Converters

🔄 PyRIT Converters Transform Prompts

Converters encode/obfuscate prompts before sending. These are PyRIT's actual converter classes from the official documentation.

How "Jailbreak Templates" Work

Step 4 does not replace your attack mode. It rewrites each prompt after it is generated. In Brute Force, it transforms each predefined prompt. In LLM-Driven, it transforms each attacker-generated prompt before the target sees it.

🔐 Encoding (EASY difficulty)
🎭 Obfuscation (EASY difficulty)
🕌 Script / Language Transform
🕵️ Token Smuggling
📝 Formatting
🧠 LLM-Based (Requires LLM)
🎭 Jailbreak / Injection Templates

Not shown here: image/audio/video/PDF/Word-doc converters (e.g. AddImageTextConverter, AzureSpeechTextToAudioConverter, QRCodeConverter, PDFConverter, WordDocConverter, TransparencyAttackConverter) are intentionally excluded. This builder's attack loop converts a single text prompt string end-to-end, and those converters change the modality (input/output type) instead of transforming text, so they don't fit into a simple chained get_converter_instances() loop without a different pipeline.

📊 Step 5: Response Scoring

📊 What is Scoring?

Scoring evaluates if the attack succeeded by analyzing the target's response. It answers: "Did we achieve our objective?"

⚠️ When to Use Scoring

Required for: LLM-driven attacks (to know when to stop)
Optional for: Brute force (can manually review results)
Example: Check if response contains "password" or secret value

Scorer Type Meanings

No Scorer: no automatic success decision; you inspect responses yourself.
SubStringScorer: success if a keyword appears in the response.
RegexScorer: success if a pattern matches the response.
GandalfScorer: Gandalf-specific password checker.
SelfAskTrueFalseScorer: an LLM judge answers whether the objective was achieved.
SelfAskRefusalScorer: an LLM judge decides whether the target refused.

📋 Manual Review Mode

No automatic scoring. You'll review responses manually to determine success.
Note: Any "Scorer/Judge LLM" configured in Step 3 will be ignored.

✅ SubStringScorer

Simple and fast. Returns True if the substring is found in the response. No LLM needed.

🔍 RegexScorer

Use regex to match patterns. Good for extracting structured data like password: XXXX

🧙 GandalfScorer

Contacts the Gandalf API to verify if the extracted password is correct for the chosen level. Requires a Scorer LLM (Step 3) to extract the password from responses.

🤖 SelfAskTrueFalseScorer

Uses an LLM to judge if the objective was achieved. Requires a scorer LLM configured in Step 3.

⚠️ LM Studio / Ollama Warning

SelfAskTrueFalseScorer requires JSON mode which local LLMs (LM Studio, Ollama) do NOT support.

Use instead:
• SubStringScorer - for detecting specific keywords (no LLM needed)
• OpenAI API - if you need LLM-based scoring (supports JSON mode)

🚫 SelfAskRefusalScorer

Detects if the target refused to comply. Useful for measuring how often the target blocks requests.

⚠️ LM Studio / Ollama Warning

SelfAskRefusalScorer requires JSON mode which local LLMs do NOT support.
Use OpenAI API or Azure OpenAI for this scorer.

🔍 PyRIT Scanner - AIRT Scenarios

PyRIT 1.0.0 scorer compatibility

LLM-backed AIRT scorers can request structured output. If PyRIT sends json_object and LM Studio rejects it because it requires json_schema, enable the generated Option A compatibility proxy. The proxy performs the response-format translation without patching PyRIT.

PyRIT 1.0.0 custom-target compatibility

Generated scanner commands use --start-server. Technique identifiers are emitted in lowercase (for example all, not ALL). For LM Studio, scanner.env emits PyRIT's required OPENAI_CHAT_ENDPOINT, OPENAI_CHAT_MODEL, and OPENAI_CHAT_KEY; these configure the helper/scorer LLM and do not replace your custom HTTP objective target.

PyRIT 1.0.0 Scanner Flow

PyRIT 1.0.0 pyrit_scan is a REST client. This tab uses --start-server so the local pyrit_backend is launched or reused automatically. For a custom HTTP target, the generated PyRITInitializer registers the HTTPTarget, while scanner.env configures the LM Studio/OpenAI-compatible helper model using PyRIT's required OPENAI_CHAT_* variables. The custom web application remains the objective target registered by custom_target_init.py.

📦 Scanner Setup Files And Commands

For custom HTTP scanner runs, use the generated initializer script plus scanner YAML config. Provider credentials can remain in .env; .pyrit_conf is optional when the generated config is passed explicitly. 

.env
Purpose: scorer/helper model credentials used by PyRIT itself

.pyrit_conf
Purpose: optional global defaults for env files and memory settings

custom_target_init.py
Purpose: registers your HTTP target as gandalf_target (or your chosen name)

pyrit_custom_scan.yaml
Purpose: scanner startup config with in_memory + correct initializer order

⚠️ Custom Scanner Targets Use Two Commands

For custom HTTP targets, the safest flow is:
1. Start pyrit_backend with your generated scanner YAML
2. Run pyrit_scan against http://localhost:8000

The builder below now generates both commands for you.

⚠️ Scanner Scorers Need A Compatible Judge Model

Your custom HTTP target can work even when the scanner still fails.
AIRT scenarios also call PyRIT scorers/helper chat targets from .env.
If the scorer endpoint rejects structured outputs with errors like 'response_format.type' must be 'json_schema' or 'text', switch OPENAI_CHAT_* to a more compatible model/provider.

🔌 Proxy Configuration (Optional)

PyRIT's HTTPTarget supports httpx proxy settings, same as the Custom Script Builder tab - use this to route the objective-target traffic (the calls to your app-under-test, e.g. Gandalf) through Burp Suite or mitmproxy for inspection.

Leave Proxy URL blank for normal runs. When set to a Burp/mitmproxy address, this proxies only your custom HTTP target's own traffic - it's independent of the scorer/attacker debug-proxy env vars generated below.

Technique dependency

Select a scenario/technique. PyRIT 1.0.0 will indicate whether an adversarial chat target is required.

LM Studio normally does not require an API key. Leave it blank unless your local server is configured to require one.

Used by adversarial techniques such as red_teaming, tap, pair, role-play, context-compliance and simulated Crescendo.

OpenAI API requires an API key.

The scorer is independent from the attacker model. PyRIT scenarios may use LLM-backed scorers even when the selected attack technique itself does not need an attacker LLM.

LM Studio structured-output compatibility proxy (Option A)

Enable this when the scorer is LM Studio and PyRIT sends response_format.type=json_object but LM Studio accepts json_schema. The generated proxy listens locally, rewrites only that incompatible response-format field, and forwards the request to LM Studio. PyRIT itself is not modified.

🕵️ HTTP Debug Proxy (Burp Suite / mitmproxy)

Optional. Route PyRIT's outbound HTTP calls through an intercepting proxy like Burp Suite or mitmproxy so you can inspect the exact request/response bodies (this works for any provider - OpenAI, Azure, LM Studio, your custom HTTP target, all of it). This is separate from the LM Studio compatibility proxy above; you can use either independently or both together (chained).

Loopback HTTP traffic (LM Studio, your custom target, this compatibility proxy) needs no certificate setup. If your scorer/attacker provider is a cloud HTTPS endpoint (OpenAI, Azure), install Burp's CA certificate first or Burp will only show a TLS handshake, not the decrypted request.
